# VIBE FM — automatic funk effects

<img src="https://github.com/kesi03/wah-wah/raw/master/firmware/wah-wah/icon.png" alt="drawing" style="width:200px;"/>

A 70s funk effects pedal for VIBE FM. It is an **effect first**: guitar/bass enters on **IN 1** and runs through the whole chain. The wah sweeps itself, follows your picking, talks, or tracks a real expression pedal — the Leslie spins itself. No pedal is required for the automatic modes.

For testing without an instrument, the 25 keys pluck a tiny built-in Karplus-Strong guitar. The hands-free funk riff starts only when you press the DEMO button (F6 / K6 / PLAY, or the editor's Demo riff button). Those keys are only a showcase; the same FX process the live input.

## What is in the box

```
firmware/wah-wah/
  main.c          parameters, presets, keys/demo guitar, display, editor bridge
  fx.c / fx.h     the DSP: gate -> comp -> wah -> drive -> EQ -> mod -> delay -> reverb -> Leslie
  editor/index.html  custom 70s editor page (afro logo, animated wah needle and rotor)
  icon.png        960x540 firmware tile, generated by tools/make_icon.py
  firmware.json   VIBE FM manifest (id: wah-wah, protocol 7)
scripts/fetch-sdk.sh
tools/make_icon.py
.github/workflows/build.yml
```

The firmware uses `VIBE_PARALLEL_AUDIO`: control flow publishes coefficient snapshots through a seqlock; the audio flow only reads them. No heap, no libc, no host calls from the audio path.

## Build and install

The SDK is pinned to commit `2ac234088ee5e2da4503f380f3a167d253cc75d4`. You need Zig 0.13.0 (`zig` on `PATH`, or set `ZIG=/path/to/zig`) and Shell (`sh`).

```sh
sh scripts/fetch-sdk.sh
sh sdk/tools/build.sh ../firmware/wah-wah
```

That produces `sdk/build/wah-wah.wasm`. On Linux/macOS the script also packs `sdk/build/wah-wah.zip`; drop the zip onto the VIBE FM VST window to install. The zip contains the `.wasm`, `firmware.json`, `icon.png` and `wah-wah.editor/index.html`.

Validate and render a test:

```sh
node sdk/tools/vibe-check.mjs sdk/build/wah-wah.wasm --manifest firmware/wah-wah/firmware.json --seconds 5
node sdk/tools/wasmtest.mjs sdk/build/wah-wah.wasm script.json out/
python tools/make_icon.py        # regenerate the afro icon if you change the motif
```

On Windows, `vibe-check` may need `HOME` set (for example `$env:HOME = 'C:\Users\{{name}}'` before running it). If `python3` resolves to the Microsoft Store alias, the WASM still builds; pack the zip with your installed Python instead:

```sh
python -c "import zipfile,pathlib; b=pathlib.Path('sdk/build'); z=zipfile.ZipFile(b/'wah-wah.zip','w',zipfile.ZIP_DEFLATED); [z.write(p,p.relative_to(b)) for p in sorted(b.rglob('wah-wah*')) if p.is_file() and p.suffix in ('.wasm','.json','.png')]; [z.write(p,p.relative_to(b)) for p in sorted((b/'wah-wah.editor').rglob('*')) if p.is_file()]; z.close()"
```

## Signal path

```
IN 1 + demo guitar (keys / riff)
  -> noise gate -> compressor -> WAH -> drive -> 3-band EQ
  -> chorus / flanger / phaser -> ping-pong delay -> reverb -> LESLIE -> OUT L/R
```

### Wah engine

The wah is an original state-variable band-pass design with a logarithmic pot sweep, resonance that relaxes toward the toe, smooth coefficient changes and its own pre-drive. Six controllers share it:

- `OFF` — bypass the wah stage (the gate/compressor/drive chain still runs).
- `SWEEP` — LFO from 0.1–10 Hz with Depth and four shapes: SINE, TRIANGLE, SAW, SQUARE.
- `ENVELOPE` — follows the input level in dB; Sensitivity, Attack, Release and Hold decide how far it opens and how long it stays there.
- `TOUCH` — a one toe-kick per picked note, then a decay; useful for sharp funk chops.
- `TALK` — a faster sweep plus a second formant above the main band for a vowel-ish "wokka" sound.
- `PEDAL` — follows an expression jack, the pedal switch, or MIDI CC4 / CC11 / CC1. The switch toggles wah on/off into the last mode.

Three voicings change the pot curve, resonance and band gain: `CRYBABY` (tight, nasal), `VOX` (broad and vocal) and `BASS` (low, sharper peak). Low/High set the heel and toe of the sweep; Wah Drive adds grit before the main drive stage.

- **Leslie**, adapted from BAR-FLY's clean-room dual-rotor model: an 800 Hz crossover feeds independent horn (~0.9 / 7 Hz) and drum (~0.8 / 6 Hz) motors with separate spin-up, brake and stop times. Three baffle taps per rotor add geometry-based Doppler and inverse-distance gain, then a horn-voicing/drive stage and a stereo mic pair complete the sound. Rotor speed is `STOP / SLOW / FAST`; `RAMP` (0.05–10 s, baseline 1.5 s) scales the motor time constants rather than a single rotor glide. On/off is crossfaded and the motors coast while the mix fades.
- Drive, gate, compressor, EQ, modulation, delay and reverb are all always in the same chain; the demo keys do not bypass anything.

## Factory presets

`FUNK WAH`, `ROTARY`, `WAH + ROTARY`, `FUNK DUB`, `CLEAN`, `TALK BOX`, `BASS WAH`. `F1` / `K5` step through all seven; the editor has buttons for each. Presets do not start the demo riff. A saved rig wins over the factory default on startup, except that the riff is always off until you press the DEMO button; `Save rig` in the editor (or `VIBE_EV_SAVE`) writes it.

| --- | --- |

| MIDI CC4 / CC11 / CC1 | Foot controller / expression / mod wheel also drive PEDAL mode |
| HOME | Show the controls overview |
| RETURN | Back to the main page |
| REC / STOP / PLAY | Panic / riff off / riff on |

### Editor page

The custom `editor/index.html` is the main UI: it has the afro branding, a moving wah needle driven by the live cutoff readout, a CSS rotor driven by the live rotor speed, all parameters, seven preset buttons, pluck buttons, and rig save/reset/panic. It uses only `window.vibe` and no external assets. The firmware remains fully playable without it.

Editor byte commands: `0x20` status request, `0x21` save rig, `0x22` reset to `FUNK WAH`, `0x23` panic.

## Parameters

All parameters use stable string ids and are stored/transferred as `value × 1000`. The standard Editor has four tabs: WAH, FX (Leslie, dynamics, modulation, delay and reverb), TONE and SYSTEM. The five new wah parameters were **appended** at indices 33–37, so existing DAW automation keeps its id/index. Rigs saved with the original 34 parameters still load; the new controls stay at their defaults. `leslie_ramp` still has its original id/range, but now scales the dual motor spin-up/brake times (1.5 = the BAR-FLY baseline).

## Status

The firmware builds and passes `vibe-check` (format, manifest, icon, editor page, protocol 7, parallel audio, robustness, realtime). Scripted `wasmtest` renders produced finite audio for every wah mode; the pedal sweep moved the low/mid balance from 21.1/23.2 dB at heel to 7.0/36.7 dB at toe. Leslie renders confirm the new model: mono when off, ~1.65 stereo difference ratio when on, ~0.75 Hz modulation at SLOW, ~6.1 Hz at FAST, correct following after a speed change, and a clean fade back to mono on off. Storage restart, random events and audio-path checks pass without errors.
